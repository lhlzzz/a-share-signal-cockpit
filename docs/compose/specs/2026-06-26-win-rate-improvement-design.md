# xiaogu 胜率提升设计方案

> 目标: 48% → 60%+ 胜率 (T+1 close)

## [S1] 问题诊断

当前系统 48% 胜率，接近随机。根因分析:

### 1.1 星期效应 (最大杠杆)

| 星期 | 胜率 | 票数 | 结论 |
|------|------|------|------|
| Monday | 0% | 4 | 禁入 |
| Tuesday | 33% | 3 | 弱势 |
| Wednesday | 100% | 1 | 强势 |
| Thursday | 75% | 8 | 最优 |
| Friday | 0% | 1 | 禁入 |

**周一和周五出票胜率为 0%。** 这是最大的改进杠杆。

### 1.2 高分陷阱

| 分数段 | 胜率 | 结论 |
|--------|------|------|
| 0-60 | 25% | 弱 |
| 60-80 | 71% | **最优** |
| 80-100 | 50% | 中等 |
| 100+ | 0% | 禁入 |

**100+ 分数段 0% 胜率。** 高分=追高=亏损。

### 1.3 信号强度与收益负相关

赢家 signal_pct=0.26 vs 输家 signal_pct=3.41。高信号=追高=亏损。

## [S2] 改进方案

### 方案 A: 日历过滤 + 分数截断 (最小改动)

**改动:**
1. Runner 添加星期过滤: 周一、周五不出票
2. scoring_config 添加 `max_score_cap = 95`，超过 95 分的候选降权
3. scoring_config 添加 `weekday_blocklist = [0, 4]` (周一=0, 周五=4)

**预期效果:**
- 去掉 5 个周一/周五亏损票 (0% 胜率)
- 去掉 3 个 100+ 分数亏损票 (0% 胜率)
- 胜率从 27/56=48% → 至少 27/48=56%

**风险:** 低。只做过滤，不改评分逻辑。

### 方案 B: 候选池扩大 (中等改动)

**改动:**
1. Scanner 输出 top 5 候选 (当前只输出 top 1)
2. Runner 从 top 5 中选最优
3. 添加候选多样性检查 (不同板块/不同信号类型)

**预期效果:**
- 候选池从 1-2 票扩大到 3-5 票
- 有更多选择空间

**风险:** 中。需要改 scanner 输出格式。

### 方案 C: 动态仓位管理 (高级改动)

**改动:**
1. 根据胜率历史动态调整出票数量
2. 高置信度日出 2-3 票，低置信度日 NO_PICK
3. 基于 rolling window 胜率决定是否出票

**预期效果:**
- 避开低置信度日
- 提高平均收益

**风险:** 高。改动大，需要长期验证。

## [S3] 推荐方案

**推荐: 方案 A (日历过滤 + 分数截断)**

理由:
1. 改动最小，风险最低
2. 星期效应是最强的信号 (0% vs 75%)
3. 可以立即验证效果
4. 为后续方案 B/C 打基础

**实施步骤:**
1. 在 scoring_config 添加 weekday_blocklist 和 max_score_cap
2. 在 runner 的 paper_pick_eligibility_profile 中添加星期检查
3. 在 runner 的 contrarian_re_score 中添加分数截断
4. 重新回测验证
5. 部署到生产

## [S4] 成功标准

- 胜率从 48% 提升到 55%+ (T+1 close)
- 涨停率不低于当前 2%
- 平均收益不低于当前 +0.37%
- 无新增 dead code
- 所有测试通过
- API 12 端点正常

## [S5] 验证方法

1. 历史回测: 用 DB 中 56 条有收益的记录验证
2. 前向验证: 部署后观察 1-2 周实际表现
3. 对比基准: 与改进前的 48% 胜率对比
