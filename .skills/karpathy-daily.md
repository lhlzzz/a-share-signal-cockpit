# Karpathy Skills 日常使用指南

## 使用场景

每次编写、审查或重构代码时，必须遵循以下约束：

## 核心约束

### 1. 思考再编码
- 明确陈述假设
- 如果不确定，先问
- 如果有更简单的方案，提出
- 如果不清楚，停止并说明

### 2. 简单优先
- 不写超出需求的功能
- 不为单次使用代码创建抽象
- 不添加未请求的"灵活性"
- 200行能50行完成的，重写

### 3. 精准修改
- 只改必须改的
- 不"改进"相邻代码
- 匹配现有风格
- 每行改动都要追溯到用户请求

### 4. 目标驱动
- 定义成功标准
- 循环直到验证通过
- 多步骤任务要列出验证点

## 检查清单

每次提交代码前检查：
- [ ] 是否有更简单的方案？
- [ ] 是否过度设计？
- [ ] 每行改动是否必要？
- [ ] 成功标准是否明确？
